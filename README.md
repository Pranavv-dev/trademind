# TradeMind

An agent-based algorithmic trading system for Indian equity markets (NSE), built on
Zerodha Kite Connect. Signals are generated by independent strategy agents, filtered
through a risk manager, and executed against a paper broker by default — or a live
broker if you explicitly opt in.

---

## Why this exists

Wiring a trading system end-to-end is most of the work, and most of it has nothing to
do with the strategy: market data, tick aggregation, order state, position accounting,
risk gates, daily broker re-auth, scheduling, alerting. TradeMind is that plumbing,
running unattended through a full Indian market session — plus the evaluation harness
that tells you whether a strategy on top of it actually works:

- a cost-aware, cross-sectional backtest that models **real Indian brokerage charges**
  (STT, exchange fees, GST, stamp duty, SEBI turnover) and slippage,
- a factor **information-coefficient** study that diagnoses *why* a signal fails
  rather than just reporting that it did,
- walk-forward cross-validation, with point-in-time index-membership scaffolding
  to fight survivorship and lookahead bias (built, but **not yet seeded** — see
  [Known gaps](#honest-status)).

The strategy is the replaceable part; the harness is the contribution. It has already
earned its keep once — it's how the shipped momentum signal was found to have negative
expectancy, written up in [Honest status](#honest-status) and, in full, in
[`docs/SIGNAL_EDGE_FINDINGS.md`](docs/SIGNAL_EDGE_FINDINGS.md). It ships in paper mode.

check before it becomes an order. The risk manager is a hard gate, not advice.

## Quickstart

**Prerequisites:** Docker + Docker Compose. A Zerodha Kite Connect app (for market
data) and a Gemini API key are optional — the system starts without them, with
reduced functionality.

```bash
git clone https://github.com/Pranavv-dev/trademind.git
cd trademind

cp .env.example .env      # then fill it in — see Configuration below
                          # .env is gitignored. Never commit it.

docker compose up -d db redis
docker compose run --rm backend alembic upgrade head
docker compose up -d
```

- Dashboard → http://localhost:3000
- API docs → http://localhost:5000/docs

Common tasks are wrapped in the `Makefile`:

```bash
make dev        # up with the dev override (hot reload)
make test       # pytest  ⚠️ drops your dev database — see below
make lint       # ruff check + format check
make migrate    # alembic upgrade head
make logs       # follow all containers
make down       # stop, preserving volumes
```

Two destructive commands to know about:

- **`make test`** — `backend/tests/conftest.py` runs `create_all`/`drop_all` against the
  *same* database the dev stack uses, so running the suite drops your tables. If you have
  paper-trade history you care about, run against a throwaway stack instead:
  ```bash
  docker compose -p trademind-test up -d db redis
  docker compose -p trademind-test run --rm --no-deps backend pytest -q
  docker compose -p trademind-test down -v
  ```
- **`make clean`** — runs `docker compose down -v`, destroying the Postgres and Redis
  volumes. Use `make down` for a normal stop.

### Connect market data

With `KITE_API_KEY` and `KITE_API_SECRET` set, visit `GET /api/auth/kite/login`, follow
the returned URL, and complete the Zerodha login. The callback stores an access token in
Redis, loads the instrument master, and connects the live tick stream.

Kite access tokens **expire daily and there is no refresh token**, so an unattended
deployment needs to re-authenticate every morning. TradeMind can do this via TOTP —
read [SECURITY.md](SECURITY.md#unattended-auto-login-highest-risk-feature) first,
because that feature requires storing your broker password and TOTP seed on disk.

## Configuration

All configuration is environment variables, loaded by `pydantic-settings` from `.env`.
[`.env.example`](.env.example) is the complete annotated reference. Nothing is required
to boot.

| Group | Variables | Notes |
|---|---|---|
| Database | `DATABASE_URL`, `DB_*` | Defaults work under Compose |
| Redis | `REDIS_URL` | Cache + Celery broker |
| Broker | `KITE_API_KEY`, `KITE_API_SECRET`, `KITE_REDIRECT_URL` | Market data + live orders |
| Auto-auth | `KITE_AUTO_AUTH_ENABLED`, `KITE_USER_ID`, `KITE_PASSWORD`, `KITE_TOTP_SECRET` | **Off by default. High risk — see SECURITY.md** |
| LLM | `GEMINI_API_KEY`, `GEMINI_MODEL` | ReasoningAgent only — the sentiment agent is keyword-based |
| Alerts | `DISCORD_WEBHOOK_URL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | Both optional |
| Trading | `TRADING_MODE`, `DEFAULT_CAPITAL` | **Keep `TRADING_MODE=paper`** |

`TRADING_MODE=paper` is the default and routes every order to the simulated broker.
Setting it to `live` sends real orders with real money to your Zerodha account. Given
the [documented negative expectancy](docs/SIGNAL_EDGE_FINDINGS.md) of the default
strategy, don't.

## Research tooling

The evaluation harness is usable independently of the live system.

```bash
# Cost-aware backtest of the real ProactiveAgent signal
docker compose exec backend python -m app.backtest.proactive_backtest

# Factor information-coefficient study (Spearman vs forward returns)
docker compose exec backend python -m app.backtest.factor_study

# Backfill ~5y of daily candles from yfinance
docker compose exec backend python -m app.data.backfill_yf
```

Results, methodology, and caveats — including a survivorship-bias caveat that qualifies
the positive numbers — are written up in
[`docs/SIGNAL_EDGE_FINDINGS.md`](docs/SIGNAL_EDGE_FINDINGS.md).
[`docs/LOSS_DIAGNOSIS_AND_ROADMAP.md`](docs/LOSS_DIAGNOSIS_AND_ROADMAP.md) is the
forensic account of how the losses were traced, and
[`docs/STRATEGY_RESEARCH.md`](docs/STRATEGY_RESEARCH.md) covers the strategy literature
review behind the current design.

## Honest status

**Engineering: working.** Agents, orchestration, risk gates, paper execution, live tick
ingestion, scheduling, unattended re-auth, notifications, and the dashboard are all
implemented, and the system runs a full market session unsupervised. **260 tests pass and
`ruff check` / `ruff format --check` are clean.**

**Strategy: negative edge.** Backtested over 5 years with realistic costs:

| Variant | Win% | Expectancy | Return | Sharpe | MaxDD |
|---|---|---|---|---|---|
| Momentum — *the current default* | 49.6% | −0.09R | **−21.2%** | **−0.77** | 26.3% |
| Inverted (mean-reversion) | 53.5% | +0.074R | +24.4% | 0.68 | 10.2% |
| Inverted + let winners run (2R) | 49.0% | +0.143R | +43.2% | 1.06 | 9.7% |

The factor study explains it: NIFTY-50 large caps **mean-revert**, and the strategy buys
breakouts and 52-week-high proximity — systematically the side that fades
(`proximity_52w` IC = −0.127 at 21 days). Inverting the entry tests positive across
bull, bear, and sideways regimes, so the *direction* looks real — but the magnitude is
inflated by survivorship bias (the test used today's index membership over 2021–26) and
the inversion is **not** what the shipped default does.

**Known gaps:** point-in-time `index_membership` is not seeded, which is the largest
methodological gap in the backtests; the API has no authentication (see
[SECURITY.md](SECURITY.md)); the test suite's `conftest.py` runs `create_all`/`drop_all`
against the **same** database the dev stack uses, so `make test` destroys local trade
history; the live path is far less exercised than the paper path;
`docs/ARCHITECTURE.md` §9 tracks the rest.

Nothing here should be run with real money until a variant clears +0.2R after costs
out-of-sample.

## Contributing

See [CONTRIBUTING.md](CONTRIBUTING.md). The most valuable contributions are the ones
that attack the evaluation: seed point-in-time index membership, break the backtest's
assumptions, find lookahead bias, or test the mean-reversion inversion out-of-sample.
Strategy PRs should come with cost-aware backtest evidence, not a plausible story.
